# LanceDB embedding contract incident — 2026-08-25

## Incident

The Telegram PDF collector received and extracted
`Purely-Nutrrition-Vadim-Zeland.pdf`, producing eight text chunks. The
incremental LanceDB index step rejected the document with:

```text
LanceDB embedding model mismatch:
expected nomic-embed-text, found nomic-embed-text-v1.5
```

The failure was intentional compatibility protection, not index corruption.
The intake transaction rolled back, retained the extracted text and chunks,
and quarantined the source PDF under `/hve-library/intake/failed/`.

## Root cause

The running index was built with the 768-dimensional
`nomic-embed-text-v1.5` model identity, while the collector and validation
code used the shorter Ollama request alias `nomic-embed-text` as both the
request name and the persisted LanceDB contract name.

Ollama exposes the installed model as `nomic-embed-text:latest`; the alias is
valid for API requests, but it is not the canonical model identity recorded in
the existing LanceDB table.

## Fix

The embedding contract is now explicit in
`knowledge/layer/embedding_contract.py`:

| Purpose | Identifier |
|---|---|
| Ollama API request | `nomic-embed-text` |
| LanceDB metadata and compatibility contract | `nomic-embed-text-v1.5` |

The index builder, incremental indexer, PDF/link chunk metadata, query path,
and knowledge-layer configuration all use the shared contract. New vectors
continue to be generated by the installed Ollama alias, while LanceDB
validation compares against the identity used by the existing table.

## Recovery and verification

The quarantined PDF was retried without rebuilding the existing index:

- indexed successfully with eight chunks;
- existing index preserved and extended from 13,932 to 13,940 rows;
- all rows report `nomic-embed-text-v1.5`;
- semantic retrieval returned matches for a nutrition/physical-wealth query;
- full test suite passed: 38 tests.

Future model migrations must use a deliberate index migration or rebuild.
Changing the contract identifier alone is only correct when the underlying
embedding model and vector dimension are unchanged.
